# 数据库与数据约束

## 1. 适用范围

- **存储类型**：SQLite 3（驱动 `github.com/mattn/go-sqlite3`）
- **适用模块**：`internal/database/` 及所有通过其访问持久化的 Handler / Agent 逻辑
- **不适用**：知识库原始文件（`knowledge_base/` 等目录）、运行时上传附件目录（配置指定）、Eino checkpoint / workspace 等**文件系统**状态（路径由 `config` 与 `database.DB` 字段管理，非 SQL 表）

## 2. 数据库文件

| 库文件 | 默认路径 | 主要内容（据 `architecture.md`） |
| :--- | :--- | :--- |
| 会话与业务库 | `data/conversations.db` | 对话、消息、过程详情、分组、工具执行、HITL 日志、WebShell/C2/项目/漏洞/批量任务、RBAC 等 |
| 知识库 | `data/knowledge.db` | 向量索引、检索日志、知识库元数据 |

实际路径可由 `config.yaml` 配置；部署时以运行配置为准。

## 3. 连接与运行时行为

`internal/database/database.go` 中的既定行为（修改前须评估影响）：

- WAL 模式；`MaxOpenConns=25`、`MaxIdleConns=5`
- `wal_autocheckpoint`、`journal_size_limit`（256MB）控制 WAL 膨胀
- 后台 PASSIVE checkpoint 循环（约 300s）

**架构含义**：SQLite 单写者；单体部署为主，多实例扩展不属当前设计目标。

## 4. 数据模型约束

- **核心实体**（非穷举）：用户/角色/权限、会话与消息、工具执行记录、知识库条目与向量、项目与事实边、资产、漏洞、工作流运行态、HITL 日志、审计相关表
- **命名**：遵循现有表/列命名风格；新增表前检索 `internal/database/*.go` 是否已有类似模型
- **项目事实（Project facts）**：由 `internal/project/` 与 database 协同；会注入 Agent 上下文，变更影响跨会话推理

具体表结构以代码与迁移为准，本文档不逐表列举（避免与代码漂移）。

## 5. 数据变更约束

### 5.1 新增表 / 字段

- 迁移逻辑放在数据库初始化或专用迁移函数，**必须幂等**（重复执行不失败、不破坏数据）
- **旧库可升级**：团队现有 `data/conversations.db` 升级后仍能启动
- 新列提供合理 `DEFAULT` 或可空，避免破坏读路径
- 添加针对迁移与核心查询的 `*_test.go`

### 5.2 历史数据兼容

- 禁止无迁移计划的破坏性变更（删列、改类型无回填）
- 大表加索引需评估锁表与体积；发布说明提醒备份

### 5.3 高风险数据操作

- 批量删除、清库、重置索引类操作须经需求确认，并考虑审计与 UI 确认
- 不得在日志或 API 响应中暴露完整凭证、会话密钥

## 6. 查询与性能约束

- 列表接口应分页；避免无界全表扫描暴露给 Web API
- 向量检索与知识库重建属重操作，应异步或带进度（见 knowledge 模块实现）
- 工具执行历史受 `monitor.retention_days` 等配置清理策略影响

## 7. 备份与恢复

- 升级或大规模迁移前备份 `data/` 与 `config.yaml`（见 `docs/zh-CN/release-process.md`）
- `data/` 不应打入公开发布包

## 8. AI 使用提示

- **修改数据结构前必须确认**：是否只需配置/YAML 而非新表；迁移是否幂等；是否同时改 Handler/OpenAPI/前端
- **不应擅自假设**：表名、字段语义、外键关系；应读 `internal/database` 现有代码与测试
- **规则不明确时**：查阅 `docs/zh-CN/developer-guide.md` 数据库节、`contributing-guide.md` 数据库 Checklist，必要时在需求工作区记录待确认项
