# 发布与部署约束

## 1. 适用范围

- **适用**：主服务 `cmd/server` 构建产物、随包发布的静态资源与配置示例、升级脚本
- **相关环境**：本地开发、内网测试（具体生产拓扑 **待团队后续补充维护**）
- **不适用**：`plugins/`、`mcp-servers/` 的独立发布流程（见各自 README）

> **状态说明**：当前规则仅沉淀仓库内**已有**的构建与发布文档事实；内部生产部署形态（VM/K8s/内网制品库等）尚未写入，标为「待维护」。

## 2. 构建与发布路径

### 2.1 本地 / 开发构建

```bash
go build -o cyberstrike-ai ./cmd/server
```

### 2.2 一键部署（开发/试用）

```bash
chmod +x run.sh && ./run.sh
```

`run.sh` 负责：环境检查、Python venv、`requirements.txt`、Go 依赖、编译、启动。默认 HTTPS + 根目录 `config.yaml`；明文 HTTP 使用 `./run.sh --http`。

### 2.3 发布包应包含的内容

据 `docs/zh-CN/release-process.md`，发布包应包含：

- `cyberstrike-ai` 二进制
- `web/templates/`、`web/static/`
- `config.yaml` **示例**（非含密钥的生产配置）
- `tools/`、`roles/`、`skills/`、`agents/`
- `docs/`、`README.md` / `README_CN.md`、`LICENSE`

**不得**包含：本地 `data/`、真实密钥 `config.yaml`、上传附件、日志。

### 2.4 仓库内升级脚本

根目录存在 `upgrade.sh`、`upgrade-from-zip.sh`、`restore-from-backup.sh` 等；具体使用场景以脚本注释与 `docs/zh-CN/deployment.md` 为准。

## 3. 部署约束（当前已知）

| 项 | 约束 |
| :--- | :--- |
| 进程模型 | 单体进程；默认监听 `config.yaml` 中 `server.host` / `port` |
| TLS | 生产建议配置 `tls_cert_path` / `tls_key_path`；本地可用自签 |
| 数据持久化 | `data/` 目录可写；SQLite 与上传文件依赖本地磁盘 |
| Python | 部分工具依赖 venv/`requirements.txt`；`run.sh` 会处理 |
| 横向扩展 | 架构上不天然支持多实例写同一 SQLite（见架构说明） |

安全配置见 `docs/zh-CN/security-hardening.md`、`docs/zh-CN/security-model.md`。

## 4. 发布前检查（维护者）

据 `docs/zh-CN/release-process.md`，发布前至少：

**文档与配置**

- README 功能说明、新增配置项、`config.example.yaml` 注释
- OpenAPI、中英文 i18n、高风险功能安全说明

**测试**

```bash
go test ./internal/...
```

若改动入口/构建：

```bash
go test ./cmd/...
go build -o cyberstrike-ai ./cmd/server
```

前端手测：登录、流式对话、设置保存、工具列表、控制台无错。

**升级**

- 停服务 → 备份 `config.yaml` 与 `data/` → 备份自定义 `tools/roles/skills/agents/knowledge_base`
- 升级后验证模型、工具列表、知识库、外部 MCP、C2/WebShell 启用状态、日志与审计

## 5. 内部仓库发布节奏

- 日常功能在 **`开发分支`** 提交，并同步 `origin` 与 `gitlab`
- `main` 用于吸收 `upstream` 更新；验证后再合并到开发分支
- 内部生产发版流程、制品命名、环境晋升 **待后续在本文件或 `docs/zh-CN/deployment.md` 补充**

## 6. 风险点

| 风险 | 说明 |
| :--- | :--- |
| 配置含密钥被打包 | 发布前检查归档范围 |
| 跳过 `data/` 备份升级 | SQLite 迁移失败可能导致需还原 |
| 未测流式 SSE | 反向代理缓冲导致「假卡死」 |
| 高风险模块默认开启 | C2/WebShell 须在授权环境按配置关闭或审批 |
| 多实例部署 | 未设计为无状态水平扩展 |

## 7. AI 使用提示

- **修改构建/部署相关代码前**：确认是否仅影响开发脚本还是用户升级路径；阅读 `release-process.md`
- **不应擅自改动**：`run.sh` 默认 HTTPS 行为、升级脚本的破坏性步骤，除非需求明确
- **生产相关问题**：当前文档不足时，在需求中标注「待运维补充」，不编造内网发布流程
