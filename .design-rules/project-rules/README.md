# 项目专属规则模板说明

本目录用于提供项目初始化阶段可直接复用的最小模板，帮助技术经理快速生成项目专属规则第一版。

当前模板围绕“5+X”模型组织：

- `5`：所有项目建议具备的最小专属规则
- `X`：按项目类型按需扩展的专项规则模板

## 1. 推荐使用方式

建议在项目初始化时按以下顺序使用本目录：

1. 先阅读 `project-init-spec.md`
2. 结合老项目或新项目初始化指南确定当前项目属于哪一类
3. 先生成最小必需 5 项
4. 再根据项目特点选择是否补充扩展模板

## 2. 模板选择规则

### 2.1 最小必需模板

以下模板建议所有项目初始化时都具备：

- `项目概览.md`
- `技术栈与运行方式.md`
- `系统架构说明.md`
- `模块地图.md`
- `项目编码补充约束.md`

### 2.2 条件扩展模板

以下模板按项目特征决定是否补充：

- `UI与交互约束.md`
  - 当前项目存在明显前端页面、交互规范或设计一致性要求时补充
- `数据库与数据约束.md`
  - 当前项目存在明显数据模型、报表、查询性能或数据兼容边界时补充
- `发布与部署约束.md`
  - 当前项目构建、部署、环境差异或发布路径复杂时补充

### 2.3 不建议机械全开

模板的目标是表达真实项目边界，不是为了把目录填满。  
如果某类边界在当前项目中并不重要，不建议为了“看起来完整”而机械创建对应模板。

## 3. 最小必需 5 项

当前提供以下模板：

1. `项目概览.md`
2. `技术栈与运行方式.md`
3. `系统架构说明.md`
4. `模块地图.md`
5. `项目编码补充约束.md`

## 4. 扩展模板

当前提供以下扩展模板：

- `UI与交互约束.md`
- `数据库与数据约束.md`
- `发布与部署约束.md`

扩展模板不是所有项目都必须具备，应按真实项目场景选择。

## 5. 使用原则

- 模板用于帮助快速启动，不要求逐字照抄
- 模板内容应以当前项目真实情况为准，不应为了填满模板而编造规则
- 第一版模板可以偏简，但应足以指导后续需求开发
- 当项目发生明显变化时，应同步更新对应规则文件

## 6. 与需求工作区模板的边界

本目录只负责**项目专属规则模板**，不负责定义每个需求工作区中的执行模板。

两者分工如下：

- 本目录中的模板：用于项目初始化，生成项目级长期规则
- `.design/<需求工作区>/` 中的内容：用于承载单个需求的分析、设计、计划和执行记录

如果需要查看需求工作区中的默认结构、接手页或执行进展模板，应优先查阅：

- `.design-rules/workspace-spec.md`

## 7. CyberStrikeAI 初始化状态

- **规则路径**：`.design-rules/project-rules/`（本目录）
- **仓库形态**：单仓；逻辑项目根目录为仓库根
- **使用场景**：内部二次开发（`origin` + `gitlab` 开发分支；`upstream` 为开源上游）
- **需求工作区**：`.design/` 在首条真实需求时再建立
- **责任人**：未指定（待团队指派）

不要把项目专属规则模板和需求工作区模板混在一起，否则容易导致：

- 项目规则和需求记录职责不清
- 模板层级混乱
- 后续维护时重复更新
